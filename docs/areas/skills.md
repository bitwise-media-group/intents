# Authoring skills

An intent is only as good as its request, and an approval only as good as the review behind it. This intent adds a
plugin to the [bitwise skills marketplace](https://oss.bitwisemedia.uk/skills/), so the guidance on this site is
available where people and coding agents write:

- **Write an intent** to the contract: outcome first, observable acceptance, specific invariants, an effort that fits
  one build, and plain visible text.
- **Split a large request** into dependency-ordered intents, each with a usable outcome on its own.
- **Review a plan** before approving it: scope creep, hidden text, unrequested repositories or egress, and estimates
  against the granted budget.

The skills work standalone and run `patchy lint intents` when it is available.
