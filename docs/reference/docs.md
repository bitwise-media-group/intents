# Working on the docs

This site is [Zensical](https://zensical.org), built with uv through the toolchain's python archetype. Its look comes
from the [flux-containers](https://oss.bitwisemedia.uk/flux-containers/) and
[toolchain](https://oss.bitwisemedia.uk/toolchain/) sites: the same `docs/stylesheets/extra.css` tokens and header
partials, with a landing page in `overrides/home.html`.

```sh
make serve        # http://localhost:8004, live reload for docs/ edits
make docs-build   # render into site/
```

Both commands regenerate the intent pages first. Re-run `make serve` after changing an intent file.

## Generated pages

The intent pages and several fragments are generated by `scripts/gen_docs.py` from the intent files. None of it is
committed:

| Output                              | Embedded by            | Source                                        |
| ----------------------------------- | ---------------------- | --------------------------------------------- |
| `docs/intents/<id>-<slug>.md`       | the navigation         | one intent file, its dependents and its issue |
| `build/intent-docs/areas/<area>.md` | `docs/areas/<area>.md` | the intents in that area                      |
| `build/intent-docs/roadmap.md`      | `docs/roadmap.md`      | every intent's phase and dependencies         |
| `build/intent-docs/graph.md`        | `docs/roadmap.md`      | the dependency graph, as mermaid              |
| `build/intent-docs/catalogue.md`    | `docs/catalogue.md`    | every intent                                  |
| `build/intent-docs/questions.md`    | `docs/questions.md`    | every intent's open questions                 |

The generator also rewrites the intent index in `README.md`. The area pages and every other page are hand-written.
`pymdownx.snippets` runs with `check_paths`, so a page that includes a fragment that does not exist fails the build.

## Checks

`make lint` runs the intent validator and `scripts/gen_docs.py --check`. The check fails when the README index is stale,
an area has no page, or the _Areas_ section of `zensical.toml`'s nav does not list exactly the generated intent pages
under their areas. It prints the expected section to paste in.

## Publishing

`docs.yaml` builds the site and deploys it to GitHub Pages on every push to `main` that touches the docs, the intents or
the generator. CI builds it on every pull request (`mise run build`). Pages must be set to **Settings → Pages → Source →
GitHub Actions**.
